# 📬 Agent Inbox／Agent 收件匣

> 觀察外部世界如何直接把任務、討論與責任交給長時間工作的 AI 幕僚，以及 Email 如何進一步演化成任務作業系統。

────────────────

## 🏷️ 分類定位

Agent Inbox / Long-running AI Staff / Email-native Agent / Email Task Operating System

這類卡片主要觀察：

- Agent 是否擁有自己的可識別收件入口
- 是否能被 CC 進工作討論並持續追蹤任務
- 模糊、多步驟與跨天任務能否可靠延續
- Email 是否能直接轉換為可執行、可追蹤的任務工作流
- 人類介入、權限、安全與責任邊界如何設計

## 🧬 Evolution Log

### 2026-07-21｜🆕 新物種形成

Deck 與 Nitrosend 顯示 Agent 開始擁有自己的收件匣、寄信能力與 Email 通訊基礎設施。

### 2026-07-25｜🧬 Scape：從通訊入口演化成任務作業系統

Scape 把這個物種往前推了一步：

Email 不再只是 Agent 接收訊息與任務的入口，而是可以直接被解析、規劃、執行與追蹤的工作系統。

物種定位從：

> Agent 擁有自己的信箱。

演化成：

> 收件匣本身可以成為 Agent 完成工作的任務作業系統。

這也帶來新的治理要求：寄件人身分、附件、外部資料、指令與實際執行副作用必須被分開驗證。

────────────────

## 🎯 新觀察重點

- 信件如何可靠轉換成任務、子任務與完成條件？
- Agent 能否區分資訊、請求、授權與惡意資料？
- 執行後是否能回信說明結果、證據與未完成事項？
- 同一郵件串的責任、狀態與版本如何持續同步？
- Email 變成工作入口後，如何防止 Prompt Injection 與未授權操作？
