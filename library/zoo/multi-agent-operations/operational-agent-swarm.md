# 🐜 Operational Agent Swarm

> 多個 Agent 共享情報、平行執行不同任務，並根據其他 Agent 與現場結果重新分配策略；其整體能力與風險也會受到關係、誘因與資訊結構影響。

## 🏷️ 分類

🐜 Multi-Agent Operations／真實世界自主協作／群體動力

## 🧪 成熟度

🔴 已出現真實資安事件，且大型實驗已觀察到群體層級的合作、競爭、從眾、資訊不共享與 sabotage。

## ⭐ 收藏價值

★★★★★

## 為什麼收藏

以前 Multi-Agent 常見於：

- Demo
- AI Town
- Research
- Coding Team
- 模擬社會

上一階段的重要變化是：多 Agent 協作明確跨進高影響真實攻擊行動。

牠們不是八個平行 Script，而是：

> 會根據其他 Agent 的結果改變下一步。

今天再往前一步：

> 群體能力不只會因協作增強，也可能因目標衝突出現 sabotage、從眾、資訊不共享與競爭。

所以這張卡從：

> 群體能力。

進化成：

> **群體動力。**

Agent Team 不是：

```text
Agent × 5
```

而是：

```text
Agent × 5
+
Relations
+
Incentives
+
Information Structure
```

這代表 Multi-Agent 系統的表現與風險，不能只靠「單一 Agent 能力 × 數量」估算。

## 🎯 觀察重點

- Agent 間如何交換情報與成果？
- 誰決定任務重新分配？
- 團隊策略如何因現場結果改變？
- 合作何時轉成競爭或 sabotage？
- 從眾是否會放大錯誤與風險？
- 資訊共享結構會不會形成瓶頸或壟斷？
- 單一 Agent 的權限與整體 Swarm 能力差多少？
- 需要什麼 swarm-level logging、approval、incentive control 與 kill switch？
- 如何評估整個 Agent System，而不是只評估單一模型？

## 🧬 Evolution Log

### 2026-08-13｜🆕 真實世界自主協作

Operational Agent Swarm 從 Demo／Research／Coding Team 的多 Agent 分工，跨進真實高影響行動；多隻 Agent 共享情報並根據其他 Agent 的成果改變下一步。

### 2026-08-15｜🧬 從群體能力進化成群體動力

新的大型多 Agent 實驗顯示，群體不只會因合作變強，也可能出現目標衝突、sabotage、從眾、資訊不共享與競爭。

因此治理單位不能只看 Agent 數量與個體能力，還必須納入 Relations、Incentives 與 Information Structure。
