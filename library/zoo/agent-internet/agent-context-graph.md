# 🗺 Agent Context Graph

> 把組織內 API、服務、版本、Owner、Dependency 與影響範圍整理成 Agent 可持續查詢的即時知識圖。

## 🏷️ 分類

🗺 Machine-readable Organization／Agent 組織導航

## 🧪 成熟度

🟢 已作為 Production Agent Infrastructure 出現。

## ⭐ 收藏價值

★★★★☆

## 為什麼收藏

傳統 Knowledge Base 主要告訴人：

> 有什麼資料。

Context Graph 更像是在告訴 Agent：

> 現在真正的世界長什麼樣。

它把組織內部服務、版本、Owner、Dependency 與影響關係，轉成可以持續查詢的機器可讀結構。

這是 Agent 從「閱讀文件」走向：

> 組織導航

的重要一步。

## 🎯 觀察重點

- Context Graph 如何維持 freshness？
- API、服務、Owner、版本與 Dependency 是否能統一表示？
- Agent 能否據此做影響分析與責任定位？
- 如何與 Knowledge Base、Registry、A2A、MCP 分工？
- 錯誤或過期 Context 是否會造成系統性誤判？

## 🔗 關聯

- A2A Protocol
- MCP
- Cloudflare OS
- Resident Discovery / Agent Discovery
- Agent-ready Website

## 🦞 龍蝦一句話

「Knowledge Base 是公司百科；Context Graph 比較像給 Agent 的即時城市地圖。」
