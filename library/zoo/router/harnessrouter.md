# 🆕 HarnessRouter

> 透過一個 API，在產品內調用多種沙盒化 Coding Agent。

────────────────

## 🏷️ 分類

🚦 Multi-Agent Router／Agent 執行基礎設施

────────────────

## 🌱 成熟度

🌱 已推出，需觀察可靠性與成本路由能力

────────────────

## ⭐ 收藏價值

★★★★☆

────────────────

## 👍 為什麼收藏

它代表 Agent 生態的定位變化：

> Agent 不再一定是固定綁定的一位助理，而可以像運算資源一樣被動態挑選、替換與調度。

這讓產品可以依任務、成本、速度與安全需求，選擇不同 Coding Agent 與執行沙盒。

────────────────

## 🎯 觀察重點

- 路由是否只看模型名稱，還是能依可靠性與任務型態決策？
- 多 Agent 的輸出品質與行為差異如何標準化？
- 沙盒隔離、憑證、檔案與網路權限是否可治理？
- 失敗時能否安全切換 Agent，而不破壞任務狀態？
- 是否提供成本、延遲與成功率的可觀測性？
