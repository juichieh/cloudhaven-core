# 🆕 Agentshire

> 把工作 Agent 變成在小鎮中移動、交談、執行任務與慶祝的 NPC。

────────────────

## 🏷️ 類型

GitHub／3D Agent小鎮／多Agent可視化

────────────────

## ✨ 一句介紹

把工作 Agent 變成在小鎮中移動、交談、執行任務與慶祝的 NPC。

────────────────

## 🌱 成熟度

🌱 專案仍早期；生活模擬、工作流穩定性與版本相容性可能快速變動。

────────────────

## ⭐ 收藏價值

⭐⭐⭐ 值得拆解，不是現成底盤

────────────────

## 👍 為什麼收藏

Agentshire 與 Cloudhaven「把 Agent 放進可觀察世界」的方向高度相關。

尤其值得觀察：

- 任務狀態如何映射成角色行為；
- Agent 是否有自己的工坊、工作區或角色空間；
- 多 Agent 同時工作時，使用者如何快速理解誰在做什麼；
- 工作開始、進行、卡住、完成與慶祝如何被世界視覺化；
- 可觀測性是否真的比 Dashboard 更直覺。

────────────────

## 🏠 鉗鉗生活觀察箱可用

這張不是要把 Agentshire 直接當成 Living World 底盤。

比較值得拿來參考的是：

- Observation Box 的任務狀態呈現；
- Agent 工作區／角色工坊概念；
- 工作中的角色動畫與狀態泡泡；
- 多 Agent 同時存在時的可觀測性；
- 「完成任務後，世界留下可見反應」的 UX。

目前判定：

> `candidate` — 高度相關的可視化／工作狀態參考，不是現成世界基礎。

────────────────

## 🎯 觀察重點

- 角色移動是否只是裝飾，還是真正對應工作狀態？
- Agent 工坊是否能清楚表達角色能力或職責？
- 使用者是否能一眼知道哪隻 Agent 正在忙、等待、卡住或完成？
- 3D 世界是否增加理解，還是反而增加資訊噪音？
- 任務狀態與世界事件是否能穩定同步？
- 多 Agent 數量增加後是否仍然容易觀察？
- 是否有值得轉化成 Cloudhaven Bubble UX／Observation Box 的設計模式？

────────────────

## ⚠️ 不採用範圍

目前不要把 Agentshire 判定為：

- Cloudhaven World Foundation；
- 完整生活模擬引擎；
- Resident Memory 系統；
- 長期自主居民核心；
- 可直接替換 Living Stage 的現成底盤。

本卡主要研究：

> 「Agent 工作如何被放進一個可觀察世界裡。」
