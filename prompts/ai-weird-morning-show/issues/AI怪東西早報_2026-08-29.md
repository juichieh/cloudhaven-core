## 🏅 Operant Semantic Firewall：既然工人、老師都是 AI，那保全也開始看「意圖」

Operant AI 在 8 月 27 日推出 **Semantic Firewall**，想解決一個 Agent 時代特有的問題：

傳統 Firewall 很會判斷：

> 這個 IP／Pattern／Signature 是否已知危險。

但 Agent 的危險行動往往完全不像已知攻擊。

例如：

```text
讀 10 個檔案
→ 正常

把 10 個檔案打包
→ 正常

上傳到陌生 API
→ 單獨看也可能正常

三件事串起來：
→ 資料外洩
```

Operant 的產品宣稱會在 Agent 執行過程中理解 Prompt、Tool Call、Command 與 Data Movement 的「意圖」，再 inline 做：

```text
ALLOW
BLOCK
REDACT
```

而不是事後才警報。citeturn226783view3

它分成：

- Tool Intent Guard；
- Code Intent Guard；
- Data Intent Guard；

例如偵測 bulk data dump、credential access、shell breakout、未授權分享或機密資料移動。這些都是廠商宣稱，實際效果仍需更多獨立驗證。citeturn226783view3

這件事為什麼今天值得放？

因為：

> 當 AI 變成老師、工程師、研究員時，治理也不能只靠「不准做某一個 API」。

它必須開始理解：

> **這整串行動最後到底想造成什麼結果？**

這跟 Cloudhaven 的小查越來越像。

不是問：

> 鉗鉗能不能使用 Browser？

而是：

> **鉗鉗現在為什麼要用 Browser？接著要把資料送去哪裡？**

🦞 **龍蝦吐槽：**

傳統保全：

> 你有門禁卡，請進。

Semantic Firewall：

> 你有門禁卡沒錯，但你為什麼半夜抱著公司資料往停車場走？😑
